An Agents SDK agent that manages its own context

A minimal implementation of Context Language Models on the OpenAI Agents SDK. The agent's live context is a file. The agent edits that file with ordinary tools, and its next model call sends whatever the file now says.

How it works

The only thing that changes is who decides what the model sees next.

SDK default

ct+1 = ct ⊕ f(ct)

The runner appends every item to the input. Context only grows until a harness intervenes or the limit is reached.

CLMAgent

ct+1 = f(ct)

The agent decides. It can delete, rewrite, summarize, or move anything out to storage, using any strategy it can express in code.

  1. Mirror

    Before each model call, the turns are written to LIVE_CTX_MAIN.txt.

  2. Act

    The agent runs bash like any other tool call, and may rewrite that file.

  3. Sync

    call_model_input_filter reads the file back and re-pins the original task. New turns are appended.

  4. Send

    The next request is built from the file, not from the runner's append-only list.

Benchmarks

The paper's ContextBench: its official task generators, graders, level definitions, and method skills, at the paper's 32K context limit. Each task needs no reasoning or knowledge beyond following the instruction, so failures reflect context management.

Needle retention

Selective retention. Keep a few lines verbatim while discarding filler. Graded on the final context.

Sudoku sketchpad

In-place edits. Keep a 16×16 board current through a stream of moves. Each version must be exact.

KV store

Offload and retrieve. Evict batches of records, then answer exact lookups from any earlier batch.

Log triage

Offload and retrieve. Move batches of logs to disk, then answer exact lookup and count queries.

MethodWhat decides the context
BaseNothing. The SDK's default append-only behavior.
SummaryA fixed harness policy: at 75% of the budget, replace the conversation with a Codex-style handoff summary.
CLMThe agent, by editing its context file.

Effective means a higher score at high pressure (input ÷ budget) without more compute. Paper Figure 2 reports CLM near 100% at every pressure while the baselines fall away. Compute is prefix-reuse cost (paper Eq. 3): prompt tokens that fall after the first edit have to be reprocessed.

Run it

# Install and test, no API key needed
uv sync
uv run python -m pytest

# Offline demo: a scripted fake model drives the real SDK loop
uv run python -m benchmarks.run --scripted

# Real benchmark
export OPENAI_API_KEY=sk-...
uv run python -m benchmarks.run --profile pilot                  # 12 runs, about $9
uv run python -m benchmarks.run --profile figure2 --max-usd 25   # the Figure 2 ladder

# This dashboard (refreshes while a benchmark runs)
uv run python -m dashboard
from agents_clm import CLMAgent, CLMRunner, ContextSettings

agent = CLMAgent(
    name="Researcher",
    instructions="...",
    tools=[...],
    context_settings=ContextSettings(budget=32_768),
)
result = await CLMRunner.run(agent, "Your task", max_turns=100)

print(await agent.live.read())     # the context file as the agent left it
print(agent.live.trace.summary())  # peak context, prefix reuse, reference cost
